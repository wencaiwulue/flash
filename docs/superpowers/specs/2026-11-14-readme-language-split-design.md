# README 英中拆分与双语文档发布设计

本文约定实施后的文档与发布行为，不表示相关实现、测试或 CI 已经完成。

## 1. 问题与约束

当前根目录 `README.md` 将中文和英文逐段混排。英文读者必须在中文段落之间寻找英文内容，中文读者也需要跳过重复英文；修改命令、表格或限制说明时，还容易只更新一种语言。若只新增一份翻译而不约束结构，两份文档会继续漂移，发布归档也可能只带其中一种语言。

本功能解决三个相互关联的问题：

1. `README.md` 应成为英文默认入口，除语言切换标签外不再保留中英逐段混排正文。
2. `README.zh-CN.md` 应是完整的简体中文对应版本，而不是只含快速开始的节选；两份文档按相同章节顺序提供相同命令、表格信息、能力边界和限制。
3. 每个独立二进制归档都必须携带这两份根文档，解包后语言切换链接可直接使用，归档内容检查不能只验证二进制。

约束如下：

- 语言切换必须使用仓库相对链接：`README.md` 链接 `README.zh-CN.md`，后者链接 `README.md`；不能使用依赖分支名的绝对 URL。
- 两份文档必须具有相同的 heading level 序列、固定的中英文二级标题映射、相同的 code-fence info-string 序列和表格形状；排除语言入口后，其他 Markdown 链接目标也必须一致。代码块正文和注释可以翻译，命令语义等价由人工审阅，不能声称测试逐字比较代码块。
- 安装命令、手动解包和 SHA-256 校验说明属于两份 README 的共同内容；`install.sh` 的信任模型、原子替换、信号清理等安全设计由 [sh installer 设计](2026-11-14-sh-installer-design.md) 独立说明，本功能不复制该安全契约。
- 发布仍只有六个原生归档目标。归档内的成员必须恰好是一个平台二进制和两份 README，不能顺带加入整个 `docs/` 树、checksum sidecar 或安装脚本。
- Windows 归档使用 `.zip`，其余使用 `.tar.gz`，但两种归档都包含相同的文档文件名。
- 文档只能陈述发布门禁实际覆盖的版本、帮助、解包和 checksum 行为，不能从构建成功推断模型服务、可选原生集成、签名、公证或自动更新能力。
- 除语言入口外，仓库指南使用指向 GitHub `main` 分支的绝对链接，使归档中的 README 也能在线打开对应文档。归档只承诺双语 README 互链可离线解析；绝对指南链接需要网络，不承诺未打包的 `docs/` 页面可离线访问。

## 2. 设计理由与备选方案

### 2.1 为什么选择“一份英文源文件 + 一份完整中文对应文件”

按文件划分语言让默认阅读路径不再包含重复段落，同时保留仓库内直接可访问的中文入口。两份文件使用同一组逻辑章节、代码块类型、表格形状和非语言链接目标，使结构漂移检查可以落到确定的数据上，而不是依靠人工记忆。

语言链接放在 H1 之后、正文之前，确保从任一入口都能一次点击切换。英文文件允许语言标签“简体中文”这一必要的非英文文本；这不构成中英混排正文。中文文件使用 `[English](README.md)`。

“完整对应”指信息覆盖和结构对应，不声称机器可以证明自然语言翻译语义完全等价。自动测试负责章节映射、代码、链接和打包；措辞准确性、术语一致性和范围声明仍需人工审阅。

### 2.2 为什么用显式章节映射和结构比较，而不是只做文件存在检查

仅检查 `README.zh-CN.md` 存在，无法发现漏掉 Agent SDK、开发命令或限制说明的简版翻译。测试将英文和中文二级标题分别与固定标题映射比较，并比较完整 heading level 序列；同时比较 code-fence info-string 序列、逐行表格列数以及排除两个语言链接后的链接目标。

这种检查有意要求新增章节时同时更新测试中的章节映射。单侧新增章节、调整 heading 层级、改变代码块类型、破坏表格形状或让普通链接指向不同目标都会形成明确失败。代码块正文与注释不在自动逐字比较范围内，仓库树注释和 checksum 注释可以按语言翻译；命令是否保持语义等价必须由人工逐节审阅。

### 2.3 为什么由构建脚本导出唯一文档清单

`buildBinary()` 需要把同一组文件用于复制、tar 成员列表和解包后精确成员断言。如果三处各写一份数组，新增文档时最容易出现“复制了但未打包”或“打包了但未验证”的部分状态。因此导出：

```ts
export const RELEASE_DOCUMENTS = [
  'README.md',
  'README.zh-CN.md',
] as const
```

构建从该常量派生归档成员 `[binaryName, ...RELEASE_DOCUMENTS]`，复制阶段遍历同一常量，解包阶段再与该成员列表排序比较。该常量只描述随每个平台归档分发的根文档，不改变六个目标的 checksum 聚合规则，也不把安装脚本混入归档。

### 2.4 备选方案与不采用原因

| 备选方案 | 不采用原因 |
|---|---|
| 保留逐段中英混排，只增加目录 | 默认英文阅读仍被中文打断，长文档重复内容和单侧修改问题没有消除 |
| 中文只保留快速开始并链接英文其余章节 | 不满足完整中文对应版本，网络或语言切换成本转移到读者 |
| 使用构建时翻译或从注释生成 README | 引入翻译工具链和生成物一致性要求，无法自动保证技术措辞与范围声明准确 |
| 只比较两份文件的标题数量 | 标题数量相同仍可能缺章、换序或命令不同；必须有固定逻辑映射和代码内容比较 |
| 在归档中放入完整 `docs/` 树 | 扩大每个平台产物并改变精确成员契约，本功能只需要两份入口文档 |
| 把语言切换改成指向 `main` 的绝对链接 | 解包后无法离线切换，且读者可能跳到与当前版本不同的文档 |
| 在安装脚本下载时再选择一种 README | 安装器只安装二进制，额外网络请求和文档选择逻辑会扩大其安全与失败语义 |

### 2.5 工程取舍

双文件方案增加了同步维护成本，章节映射测试也需要随有意结构调整更新。相比持续混排，这个成本集中在文档修改和明确测试失败中，而不是由读者和发布用户承担。构建脚本遍历统一清单的代码很薄，不引入新依赖或运行时功能。

## 3. 目标与非目标

### 目标

- **默认入口**：`README.md` 正文为英文，保留一个指向中文对应文件的相对链接。
- **中文完整性**：`README.zh-CN.md` 以简体中文表达同一组章节、产品边界、安装步骤、开发命令和文档导航。
- **结构一致**：两份文件的 heading level 序列、固定二级标题映射、code-fence info-string 序列、表格形状和非语言链接目标一致；代码块正文与注释可翻译，命令语义由人工核对。
- **链接有效**：双向语言链接存在且指向预期文件；两份 README 的其他非语言链接目标保持一致，仓库指南使用可从归档在线打开的 GitHub 绝对链接。
- **发布完整**：六个平台归档都包含一个二进制、`README.md` 和 `README.zh-CN.md`，解包后精确成员检查通过，非 Windows 二进制仍可执行。
- **共同安装说明**：英文和中文都说明 macOS/Linux 的“下载脚本后由 `sh` 执行”安装入口、手动归档方式、版本/目录环境变量和 PATH 要求，同时将详细安全行为归属安装器设计。
- **范围准确**：保留模型连接、可选集成、签名、公证、自动更新及“标签发布前资产尚不存在”等限制，不把测试或构建描述写成实机能力证明。

### 非目标

- 不翻译 `docs/` 下所有指南，不改变它们现有的语言策略。
- 不实现自动翻译、翻译记忆库或文档生成框架。
- 不新增发布平台、修改版本规则或改变归档命名。
- 不把 `install.sh` 放入平台归档；它是独立 Release 资产。
- 不在这里设计安装器的 checksum、下载、权限、原子替换或信号处理算法。
- 不把归档中未包含的仓库指南宣称为可离线访问。
- 不记录历史测试、CI、实机模型验证或 Release 发布结果。

## 4. 架构、模块与数据流

### 4.1 入口与公共契约

文档入口和构建接口如下：

| 入口 | 输入 | 输出/副作用 | 完成条件 |
|---|---|---|---|
| `README.md` | 仓库或归档中的默认文档入口 | 英文正文及到 `README.zh-CN.md` 的相对链接 | 读者无需经过中文正文即可使用全部英文说明 |
| `README.zh-CN.md` | 语言切换或直接访问 | 对应的简体中文正文及到 `README.md` 的相对链接 | 所有逻辑章节和命令均可从中文入口获得 |
| `RELEASE_DOCUMENTS` | 无 | 只读文档文件名列表 | 内容恰好为两个根 README 文件名，无重复和路径穿越 |
| `buildBinary(target, outputDirectory)` | 原生 release target 和输出目录 | 编译、复制、打包、解包复验、sidecar 写入 | 精确三成员归档存在，解包二进制 smoke 和文档检查完成 |

`RELEASE_DOCUMENTS` 是构建/测试间的内部 TypeScript 契约，不是 CLI 参数，也不要求用户设置环境变量。`buildBinary()` 继续保持原生目标限制；本功能不开放交叉编译。

### 4.2 模块与状态所有权

| 模块 | 拥有的数据/职责 | 主要操作 | 不承担的职责 |
|---|---|---|---|
| `README.md` | 英文正文、中文入口链接、共同安装说明 | 提供默认阅读和仓库导航 | 不生成中文文件，不验证安装器安全 |
| `README.zh-CN.md` | 与英文对应的简体中文正文、英文入口链接 | 提供完整中文阅读路径 | 不维护不同版本的命令或能力声明 |
| `scripts/build-binary.ts` | `RELEASE_DOCUMENTS`、staging/extract 目录、归档成员列表 | 复制两份文档、构造 tar 参数、检查解包成员及内容 | 不发布 Release，不翻译文档 |
| `tests/releasePackaging.test.ts` | 固定标题映射、heading level、code-fence info-string、表格形状、链接和文档清单断言 | 对仓库文档做离线结构验证，对构建清单做单元验证 | 不逐字比较代码块正文，不证明命令/翻译语义，不替代真实编译/解包 smoke |
| `docs/RELEASING.md` | 维护者发布流程 | 说明每个归档携带双语 README | 不重复安装器内部安全算法 |

staging 和 extraction 仍是每次 target 构建独立拥有的临时状态。文档清单是静态只读数据，不写回 README，也不持久化翻译状态。

### 4.3 文档阅读与链接流

```text
GitHub/源码根目录或解包目录
  ├─ 打开 README.md
  │    ├─ 阅读英文正文
  │    └─ 点击 [简体中文](README.zh-CN.md)
  │              → 同目录中文文件
  │              → 点击 [English](README.md) 可返回
  │
  └─ 直接打开 README.zh-CN.md
       → 获得相同逻辑章节和命令，而不是精简版
```

语言链接只使用同目录文件名，因此源码树和恰好包含两份文档的归档都能解析。其他 `docs/...` 指南使用 GitHub 绝对 URL，在源码树和归档中都能在线打开；测试比较两种语言的非语言链接目标，但不通过公网验证外部响应。

### 4.4 构建与解包验证流

```text
buildBinary(target)
  → 编译目标二进制并完成直接 --version/--help smoke
  → 复制 binaryName 到 stageDir
  → 遍历 RELEASE_DOCUMENTS，从仓库根复制到 stageDir
  → archiveMembers = [binaryName, ...RELEASE_DOCUMENTS]
  → tar/zip 仅接收 archiveMembers，避免目录通配符带入额外文件
  → 创建与解包命令仅对 Windows 使用 --force-local，防止 C:\ 归档路径被解释为远程主机
  → 解包进程以 extractDir 为 cwd，不向 Windows tar -C 传入盘符目录
  → 解包到独立 extractDir
  → readdir(extractDir) 与 archiveMembers 排序后精确比较
  → 每个解包文档与仓库源文件逐字节比较
  → 非 Windows 检查解包二进制 executable bit
  → 对解包二进制再次执行 --version/--help
  → 为归档写 .sha256 sidecar
```

任何复制失败、缺失成员、额外成员或文档内容差异都使构建失败，不生成“部分成功”的有效归档。现有 sidecar 和 `SHA256SUMS` 仍只覆盖六个归档，不覆盖归档内部文件，也不新增 Release 资产。

### 4.5 README 共同安装内容的数据边界

两份 README 的 Standalone Binaries 章节使用相同命令：

```bash
(
  set -e
  installer="$(mktemp)"
  trap 'rm -f "$installer"' EXIT
  curl -fsSL https://github.com/wencaiwulue/flash/releases/latest/download/install.sh -o "$installer"
  sh "$installer"
)
claude-code --version
```

并说明默认安装到 `$HOME/.local/bin`，可用严格 `VERSION=vX.Y.Z` 和 `INSTALL_DIR` 覆盖；该入口只支持 macOS/Linux 的 x64/ARM64。Windows 和需要手动校验的用户继续使用归档及 `SHA256SUMS` 示例。安装脚本及 Release 资产只有在包含它们的 Release 发布后才存在，文档不能暗示所有历史 Release 都已回填安装器。

README 只陈述用户可见的“从同一 Release 下载归档和 `SHA256SUMS`、匹配并校验后安装”的概括。是否替换 symlink referent、如何创建临时文件、信号退出码等不得复制成第二套可能漂移的规范。

## 5. 失败语义与工程取舍

| 触发条件 | 检测位置 | 传播与清理 | 调用方/读者可见结果 |
|---|---|---|---|
| 中文文件不存在 | 文档测试读取文件；构建复制阶段 | 测试失败或构建抛错；本次 workDir 可在下一次构建开始时重建，不承诺失败后自动删除 | 命令以失败结束，不能将不完整 staging 当作有效归档 |
| 语言链接缺失、反向或指向绝对 URL | `tests/releasePackaging.test.ts` 的精确链接断言 | 测试失败，不修改文档 | 阻止单向导航或依赖分支的链接合入 |
| 非语言链接在两种语言间漂移，或退回归档无法解析的相对指南路径 | 非语言链接目标一致性与 HTTP(S) scheme 断言 | 测试失败，不修改文档，也不发起网络请求 | 防止归档内出现 `docs/...` 断链，不声称外部链接已在线验证 |
| 单侧新增/漏掉/换序章节 | 固定逻辑章节键与两份标题映射比较 | 测试失败并要求同步文档或有意义更新映射 | 不允许“文件存在但内容不完整”通过 |
| 一侧代码块 info-string、表格形状或非语言链接目标变化 | 离线结构比较 | 测试失败 | 阻止结构漂移；代码正文和注释可翻译 |
| 一侧代码命令语义变化 | 人工逐节对照 | 评审要求修正，自动测试不声称识别命令语义 | 两种语言提供等价操作，但不要求正文逐字相同 |
| 英文正文残留中英混排 | 排除语言切换行后的 CJK 检查加人工审阅 | 测试或评审失败 | 默认入口不再逐段重复中文；必要中文语言名除外 |
| 中文措辞范围扩大 | 人工对照 `docs/STATUS.md` 与发布契约 | 评审要求修正，自动测试不宣称发现所有语义错误 | 不把未验证能力写成已验证能力 |
| 文档复制失败或源文件在构建期间变化 | `copyFile`/解包逐字节比较 | 构建抛错，不以旧文档替代 | 归档不会静默携带空白、截断或不同版本文档 |
| 归档多出或漏掉成员 | 解包目录精确集合比较 | 构建失败，sidecar 不视为成功产物 | 只接受 binary + 2 docs，不附带安装器或临时文件 |
| 解包二进制不可执行或 smoke 失败 | 现有 mode/version/help 检查 | 构建失败 | 文档完整不能掩盖二进制失败 |
| 翻译与代码存在语义分歧但自动规则未覆盖 | 人工文档评审 | 不以测试存在代替语义审查 | 验收明确保留这一证据边界 |

构建期间没有跨版本文档迁移。回滚文档拆分不会删除用户已安装的二进制，也不改变安装器的运行行为；若安装器功能已先落地，回滚本功能时必须保留其用户可见安装说明和独立 Release 资产逻辑。

## 6. 验收标准

### 文档与链接

1. 打开 `README.md` 时，除语言切换标签外正文为英文；打开 `README.zh-CN.md` 时可获得完整简体中文对应内容，不依赖跳回英文补齐章节。
2. 两个文件在 H1 后分别包含精确的相对语言链接，双向链接目标文件存在。
3. 两份文档按固定中英文二级标题映射组织，完整 heading level 序列一致；新增逻辑章节必须在两侧和测试映射中同时出现。
4. 两份文档的 code-fence info-string 序列、表格形状及排除语言入口后的链接目标一致。代码块正文和注释可以不同，测试不得断言其逐字相等；源码构建、安装、checksum、SDK 和维护者命令的语义等价由人工核对。
5. 相对语言链接在源码树和归档中可解析；两种语言的非语言链接目标一致，GitHub 指南链接可从归档在线打开。测试不得通过访问公网来判定链接正确性。
6. 安装说明在两份文档中覆盖相同平台和限制，不把 Windows 归档支持误写成 POSIX 安装器支持，也不把 SHA-256 描述为签名或公证。

### 构建与发布归档

1. `RELEASE_DOCUMENTS` 恰好导出 `README.md` 和 `README.zh-CN.md`，无重复、绝对路径或目录成分。
2. 对每个原生 target，staging 只复制目标二进制和这两份文档，tar/zip 命令使用同一显式成员数组；Windows 创建与解包以 `--force-local` 处理盘符归档路径，解包目录通过进程 `cwd` 指定，Unix 不传递不支持的 `--force-local`。
3. 解包目录必须恰好包含三个成员；两份解包文档与源文件逐字节相同。
4. 非 Windows 解包二进制保留 executable bit，所有目标继续满足直接和解包后的版本/帮助检查。
5. `SHA256SUMS` 仍只有六个归档条目，Release 文档清单变化不增加归档数量或改变归档名称。
