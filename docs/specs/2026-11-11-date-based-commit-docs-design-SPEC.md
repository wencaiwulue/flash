# Design date-based commit documentation

> 本文是依据该提交的 diff、对应 revision 的实现与测试，以及有出处的状态记录所作的回溯性设计重建；不冒充历史提交当时已存在的原文。

## 前置状态与问题

c69c271 已提供逐提交的实质设计记录，但交付文档仍以七位 SHA 命名，并保存历史执行证据。

需要在不改动产品实现的前提下，确定日期加功能的命名规则、同日冲突处理和只保留验收标准的迁移契约。

## 目标与非目标

### 目标

- 形成可评审的命名、渲染、校验、迁移与验收设计。

### 非目标

- 本提交只保存方案设计，不实施记录或生成物迁移。

## 方案架构与数据流

设计文档把完整 SHA 保留为记录身份，把日期与显式 slug 作为输出名称，并定义 head/next 动态清单和旧文件迁移顺序。

### 文件、接口与证据关系

| 关系 | 位置 | 设计作用 |
|---|---|---|
| 变更 | `docs/superpowers/specs/2026-11-11-date-based-commit-design-docs-design.md` | 经评审的完整方案设计。 |

## 关键决策与工程取舍

- 采用显式 slug 而不是从标题猜测功能名；同日同功能使用稳定序号；历史执行结果不进入新文档。

### 备选方案与回溯分析

- 保留 SHA 路径会更简单但不满足可读命名要求；纯自动生成正文会重新引入无依据设计结论。

## 安全与协议边界

- 变更仅为设计文档，不增加凭据、协议或运行时权限。

## 验收标准

- 设计明确命名格式、冲突算法、数据契约、迁移顺序、错误处理和测试验收。
